01 · npm SDK, CLI & MCP

Zero-dependency package (@paxiom/receipts).

Install @paxiom/receipts (MIT, zero external dependencies, Node ≥18) to sign receipts on your seller endpoints or verify them locally:

npm install @paxiom/receipts

Seller middleware (Fetch / Cloudflare Workers / Next.js App Router, plus createReceiptMiddleware for Express / Node http):

import { withPaxiomReceipt } from '@paxiom/receipts';

export default withPaxiomReceipt(paidHandler, {
  privateKey: process.env.PAXIOM_PRIVATE_KEY_PEM,
  issuer: { name: 'acme-data', uri: 'https://api.acme.dev', keyId: 'seller-01' },
  serviceName: 'Orderbook Snapshot API'
});

Buyer verification & stdio MCP server:

import { verifyReceipt } from '@paxiom/receipts';

const verdict = verifyReceipt(receipt, {
  output: responseJson,
  trustedPaxiomPublicKeys: ['hsRfDKd2AWxv0KwTs3gsDLMY7nPtVGky1Tc6NWgSxIY=']
});
// -> { valid: true, trustState: 'verified', checks: { ... } }

# Or launch the stdio MCP server for Claude / Cursor / agent frameworks:
npx --yes --package=@paxiom/receipts paxiom-receipt-mcp
02 · Hosted HTTP API

Routes on api.paxiom.org.

https://api.paxiom.org base mainnet live

You can also self-host the identical server offline via node runtime/receipt-verifier/server.mjs.

MethodPathAccessPurpose
GET/healthFreeLiveness check ({ ok: true }).
GET/versionFreeService identity, active capabilities, and explicit checks / notChecked boundaries.
GET/v1/receipt/demoFreeReturns a signed demo receipt and its delivered output payload.

POST/v1/receipt/verify-live$0.002 x402 / KeyConfirms Base / Base Sepolia USDC Transfer logs via multi-RPC failover, upgrades verdict to verified, and returns a Paxiom counter-signed X-Paxiom-Receipt.
GET/.well-known/paxiom-keys.jsonFreePublished Ed25519 public keys for offline verification of Paxiom counter-attestations.
GET/.well-known/x402.jsonFreex402 v2 payment terms and Bazaar discovery schema for POST /v1/receipt/verify-live.

HTTP status codes: 200 for any completed verification verdict, 400 malformed JSON, 402 x402 payment required on /v1/receipt/verify-live, 413 payload over 256 KiB, 404 unknown route.

03 · HTTP examples

Verify offline & inspect x402 terms.

API=https://api.paxiom.org

# 1. Fetch the canonical demo receipt + output and verify it for free:
curl -s "$API/v1/receipt/demo" > demo.json
node -e 'const d=JSON.parse(require("fs").readFileSync("demo.json"));\
  process.stdout.write(JSON.stringify({receipt:d.receipt,output:d.output}))' \
  | curl -s -X POST "$API/v1/receipt/verify" \
      -H 'content-type: application/json' --data @-

# 2. Inspect x402 payment terms ($0.002 Base USDC) & Paxiom public keys:
curl -s "$API/.well-known/x402.json"
curl -s "$API/.well-known/paxiom-keys.json"
04 · Boundaries

Verification guarantees.

Explicit runtime boundaries
  • POST /v1/receipt/verify is strictly offline: it makes zero RPC or facilitator calls and reports unverified tx hashes as settlement_claimed_not_checked.
  • POST /v1/receipt/verify-live verifies canonical Base Mainnet (eip155:8453) and Base Sepolia (eip155:84532) USDC Transfer event logs directly against JSON-RPC with automatic endpoint failover.
  • Counter-attested receipts (checkedByPaxiom: true) must be verified with trustedPaxiomPublicKeys loaded from /.well-known/paxiom-keys.json so untrusted signers cannot forge Paxiom settlement confirmation.
  • Teams preferring flat monthly billing over per-call x402 can request an X-API-Key via Contact.
