01 · npm & PyPI SDKs, CLI & MCP

Zero-dependency packages (@paxiom/receipts & paxiom-receipts).

Install @paxiom/receipts (MIT, zero external dependencies, Node ≥18) to sign receipts on your seller endpoints or verify them locally:

npm install @paxiom/receipts

Seller middleware (Fetch / Cloudflare Workers / Next.js App Router, plus createReceiptMiddleware for Express / Node http — auto-parses x402 v2 PAYMENT-SIGNATURE / PAYMENT-RESPONSE headers, hashes JSON via jcs-sha256 or binary/text via raw-sha256, and emits Payment-Receipt + X-Paxiom-Receipt):

import { withPaxiomReceipt } from '@paxiom/receipts';

export default withPaxiomReceipt(paidHandler, {
  privateKey: process.env.PAXIOM_PRIVATE_KEY_PEM,
  issuer: { name: 'acme-data', uri: 'https://api.acme.dev', keyId: 'seller-01' },
  serviceName: 'Orderbook Snapshot API'
});

Buyer client helpers, key discovery, TypeScript & MCP server (built-in .d.ts declarations, zero dependencies):

import { discoverIssuerKeys, preflightX402, verifyResponseReceipt, verifyReceiptLive } from '@paxiom/receipts';

// 1. Free pre-payment seller safety & key-discovery scan:
const scan = await preflightX402('https://seller.example/v1/infer', { maxBudgetAtomic: '50000' });

// 2. Discover seller keys from /.well-known/x402-keys.json & verify offline (never throws):
const keys = await discoverIssuerKeys('https://seller.example');
const check = verifyResponseReceipt(paidResponse, {
  output: responseJson,
  expectedIssuerPublicKeys: keys.publicKeys,
  expectedPayTo: '0xSeller...'
});

// 3. Free live Base USDC settlement + Ed25519 counter-attestation:
const live = await verifyReceiptLive(check.receipt, { output: responseJson, expectedPayTo: '0xSeller...' });

# Launch local stdio MCP (includes preflight_x402_seller & verify_receipt_live) or remote HTTP MCP:
npx --yes --package=@paxiom/receipts paxiom-receipt-mcp
claude mcp add --transport http paxiom https://api.paxiom.org/mcp

Python 3.10+ reference SDK & FastAPI middleware (paxiom-receipts on PyPI, zero required dependencies):

pip install paxiom-receipts

from fastapi import FastAPI

03 · HTTP examples

Verify offline & inspect public verifier keys.

API=https://api.paxiom.org

# 1. Fetch the canonical demo receipt + output and verify it offline:
curl -s "$API/v1/receipt/demo" > demo.json
node -e 'const d=JSON.parse(require("fs").readFileSync("demo.json"));\
  process.stdout.write(JSON.stringify({receipt:d.receipt,output:d.output}))' \
  | curl -s -X POST "$API/v1/receipt/verify" \
      -H 'content-type: application/json' --data @-

# 2. Inspect published verifier Ed25519 keys & run a free preflight scan:
curl -s "$API/.well-known/x402-keys.json"
curl -s -X POST "$API/v1/x402/preflight" \
  -H 'content-type: application/json' \
  -d '{"url":"https://seller.example/paid"}'
04 · Boundaries

Verification guarantees.

Explicit runtime boundaries
  • POST /v1/receipt/verify is strictly offline: it makes zero RPC or facilitator calls and reports unverified tx hashes as settlement_claimed_not_checked.
  • Passing expectedIssuerPublicKeys (from the seller's HTTPS /.well-known/x402-keys.json) and expectedPayTo rejects unauthorized intermediary key substitution with unauthorized_issuer.
  • POST /v1/receipt/verify-live verifies canonical Base Mainnet (eip155:8453) and Base Sepolia (eip155:84532) USDC Transfer event logs directly against JSON-RPC with automatic endpoint failover.
  • Counter-attested receipts (checkedByVerifier: true / checkedByPaxiom: true) must be verified with trustedVerifierPublicKeys loaded from /.well-known/x402-keys.json so untrusted signers cannot forge settlement confirmation.
  • The public api.paxiom.org runtime is provided free of charge under bounded per-IP rate limits; high-throughput gateways and facilitators can run runtime/receipt-verifier/server.mjs in-house under the MIT license.
