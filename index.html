Developer Workflow

Three lines for sellers. One call for buyers.

Seller: Sign every delivered response

Drop-in middleware hashes the canonical response and signs the receipt header.

// npm install @paxiom/receipts
import { withPaxiomReceipt } from '@paxiom/receipts';

export default withPaxiomReceipt(paidHandler, {
  privateKey: process.env.PAXIOM_PRIVATE_KEY_PEM,
  issuer: { name: 'acme', keyId: 'seller-01' }
});

Buyer / Agent: Verify payload & settlement

Check integrity locally for free, or request a Paxiom-countersigned on-chain check.

# Free local or hosted payload verification
curl -sX POST https://api.paxiom.org/v1/receipt/verify   -H 'content-type: application/json'   -d '{"receipt": {...}, "output": {...}}'

# Discover live Base x402 verifier endpoints
curl -s https://api.paxiom.org/.well-known/x402.json
Explicit Trust States

Self-asserted is never called verified

Instead of a misleading true/false flag, Paxiom resolves every check into an explicit state so automated callers know exactly what was proven and what wasn't:

verified settlement_claimed_not_checked valid_signature_only output_hash_mismatch settlement_failed invalid_signature expired
