x402 proves a payment. Paxiom proves what the payment bought.

When an agent pays an HTTP endpoint over x402, a 200 OK is not evidence of what was delivered. Paxiom binds the request, delivered output, payment transaction, and settlement verdict into one Ed25519-signed receipt that any buyer, audit log, or downstream agent can verify.

How it works

Three lines to issue. One call to verify.

Today, paid agent APIs either return unsigned JSON or invent one-off HMAC and Ed25519 headers that no buyer wallet or framework speaks uniformly. Paxiom separates free seller issuance from independent buyer verification.

1. Sellers attach proof-bound receipts for free:

// npm install @paxiom/receipts
import { withPaxiomReceipt } from '@paxiom/receipts';

export default withPaxiomReceipt(paidHandler, {
  privateKey: process.env.PAXIOM_PRIVATE_KEY_PEM,
  issuer: { name: 'acme-data', uri: 'https://api.acme.dev', keyId: 'seller-01' },
  serviceName: 'Orderbook Snapshot API'
});
// Every response automatically includes a signed X-Paxiom-Receipt header.

2. Buyers and agents verify offline for free — or confirm on-chain settlement on Base:

# Free offline check (or run locally via verifyReceipt() / MCP):
curl -s -X POST https://api.paxiom.org/v1/receipt/verify \
  -H 'content-type: application/json' -d '{"receipt": {...}, "output": {...}}'

# Live Base USDC settlement verification + Paxiom counter-attestation ($0.002 via x402 or X-API-Key):
curl -s https://api.paxiom.org/.well-known/x402.json

Honest verdicts

Self-asserted is never called verified.

A seller signing their own receipt proves what payload they delivered and binds their public key to that claim — it does not prove that a claimed blockchain transaction actually settled. Paxiom resolves every receipt into one deterministic trust state so autonomous agents never confuse a seller's claim with verified settlement:

verified settlement_claimed_not_checked valid_signature_only output_hash_mismatch settlement_failed invalid_signature expired

When a receipt carries an unverified transactionHash, offline verification stops at settlement_claimed_not_checked. Calling POST /v1/receipt/verify-live checks the canonical Base USDC Transfer event on-chain and counter-signs a Paxiom receipt verifiable offline against /.well-known/paxiom-keys.json.
