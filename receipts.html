Why this exists

A payment response is not proof of delivery.

x402 makes paid HTTP resources effortless: an agent pays, the server answers. But a payment succeeding is not evidence of what was delivered. A buyer wallet, audit log, or downstream machine still needs to verify:

  • what resource was paid for, and what exact request was bound to that payment;
  • whether the bytes delivered match the signed SHA-256 output commitment;
  • whether on-chain settlement was independently verified or merely claimed by the seller;
  • whether a third party can re-verify the receipt months later with only a public key.

Instead of every x402 seller inventing an incompatible HMAC or signature header, paxiom.receipt.v0 defines one compact, canonical receipt object with zero-dependency tooling.

Claim boundary

Schema-valid is never called receipt-verified. In offline mode, a receipt carrying an unverified transactionHash resolves to settlement_claimed_not_checked — never verified. Only independent on-chain log verification via POST /v1/receipt/verify-live (counter-signed by Paxiom's published key) upgrades settlement to verified_settled.

The verdict

One deterministic trust state.

Every verification call returns one unambiguous trust state alongside per-check diagnostics:

verified valid_signature_only settlement_claimed_not_checked output_hash_mismatch settlement_failed invalid_signature unsupported_format expired

All fifteen trust states and their strict precedence order are documented in the specification. Read the trust states →

Try it now

Install from npm or verify over HTTP.

The reference SDK, CLI, and MCP server ship in a single zero-dependency package on npm (@paxiom/receipts, Node ≥18):

# Install in an x402 seller or buyer project:
npm install @paxiom/receipts

# Generate an Ed25519 seller keypair via CLI:
npx --yes --package=@paxiom/receipts paxiom-receipt keygen --out ./seller-key-01.pem --key-id seller-key-01

# Run the stdio MCP server (verify_receipt, explain_receipt, issue_receipt):
npx --yes --package=@paxiom/receipts paxiom-receipt-mcp

Query the live production verifier at https://api.paxiom.org:

curl -s https://api.paxiom.org/version
curl -s https://api.paxiom.org/v1/receipt/demo
curl -s https://api.paxiom.org/.well-known/x402.json
Live runtime

https://api.paxiom.org serves both free offline verification (POST /v1/receipt/verify) and live Base Mainnet settlement verification + counter-attestation (POST /v1/receipt/verify-live). Published Paxiom counter-signing keys live at /.well-known/paxiom-keys.json.
